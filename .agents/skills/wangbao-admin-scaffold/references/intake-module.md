# 单模块增量输入清单

先读取现有后台的路由、菜单、相邻页面和主题规范。告诉使用者：只需描述产品需求，不要求提供技术实现；已有截图、原型或字段表可以直接上传。

## 模块定位

1. 模块名称、解决的问题和主要使用者。
2. 模块应该放在哪个现有一级/二级菜单下；不确定时由 Skill 根据现有结构建议。
3. 本次包含哪些页面，入口页面是什么，页面之间如何跳转。

## 页面内容

4. 列表页需要的筛选条件、表格字段、行操作、批量操作和分页要求。
5. 新增/编辑需要的表单字段、必填项、控件类型、分组及提交结果。
6. 详情页需要展示的字段、状态、顶部操作和关联列表。
7. 是否需要 Tab、弹窗、抽屉、步骤流程、树形结构或导入导出。
8. 页面需覆盖的正常、空、加载、禁用、失败等状态。

## 业务规则与展示

9. 状态枚举、按钮显示条件和页面上需要体现的权限差异。
10. Mock 数据数量及需要看出的交互效果，例如 Tab 切换或分页。
11. 参考图、现有类似页面，以及必须沿用或明确不要使用的样式。
12. 明确不在本次范围内的内容，例如真实接口、审批逻辑或权限后端。

收到回答后，输出“模块增量确认单”，包括菜单位置、路由与页面清单、页面流程、字段和操作、状态、复用的现有模板、Mock 范围、假设与排除项。确认后只修改该模块及必要的菜单/路由文件。
